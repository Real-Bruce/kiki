# kiki 功能优化与新增实施方案

确认日期：2026-11-10。实施基线：**v0.2.2**。各阶段实际开发和验收状态见 [当前进度](PROGRESS.md)。

本文定义新增功能和对原有行为的调整，供 Codex 按顺序实施。现有跨屏、混合 DPI、中文输入及可编辑标注能力继续保留。

配套资料：[设计草图索引](design/next/README.md)、[验收计划](ACCEPTANCE_PLAN.md)、[验收记录模板](validation/FEATURE_ACCEPTANCE_TEMPLATE.md)。草图为方案示意，不得作为真实运行或验收截图。

## 1. 已确认范围与实施约定

- 保持 Rust 2024、固定 Rust 1.88.0、windows-rs、Win32/Direct2D/DirectWrite/WIC 和 Windows 11 x64 ZIP 交付。复用已有工程，不引入 WebView 或其他 GUI 框架。
- 本轮批准长截图、马赛克、顺序编号和取色；此前规格中将它们列为后续范围的条款由本方案覆盖。OCR、模糊、录屏/GIF、历史、放大镜、贴图再次标注等未列出的功能仍不在范围内。
- F07 人工复测后提前移除**鼠标选择工具按钮**，保留绘图箭头。设置开关使用工具条同款图标和顺序，并提供实时预览。F12 按用户复测反馈保留撤销按钮与 Ctrl+Z，重做通过 Ctrl+Y 操作。
- 依次交付 F01–F12。每项先实现并同步候选目标版本，再对该版本构建、关联回归、规定验收和解压包烟雾验证；通过后创建本地 tag，再进入下一功能。不得验收旧二进制后只改版本给新包打标签，也不得合并成一个未验收的大阶段。
- 最小修改递增第三位，小优化或独立功能递增第二位，大优化递增第一位；递增前位时后位归零。阶段表是无插入修复时的计划版本。若计划标签已被额外修复占用，按同一规则使用下一个递增且未使用的版本，并同步进度和报告名称/链接（例如 F06 的 v0.7.1 被占用则用 v0.7.2）；不覆盖或移动已有 tag。
- 设计保持暖灰、松绿、线性图标、Win11 圆角和现有六页设置导航。新增项集中在截图设置页，以分组、留白和分隔线组织；内容超出时滚动，保存状态固定在底部。

### 1.1 参数、默认值与单位

“无级调节”指支持范围内的任意整数数值，并提供滑杆、数值输入和规定的滚轮操作，不再限于三档；不表示无上限。

| 参数 | 合法范围 | 默认值 | 滚轮每格 | 持久化 |
| --- | --- | --- | --- | --- |
| 矩形线宽 | 1–64 px | 3 px | 1 px | 独立保存 |
| 箭头线宽 | 1–64 px | 3 px | 1 px | 独立保存 |
| 自由画笔线宽 | 1–64 px | 3 px | 1 px | 独立保存 |
| 文字字号 | 8–256 px | 24 px | 1 px | 保存 |
| 截图圆角半径 | 0–256 px | 0 px | 不占用画布滚轮 | 保存，设置页滑杆/数值步长 1 px |
| 马赛克颗粒边长 | 2–64 px | 12 px | 1 px | 保存 |
| 编号圆直径 | 16–128 px | 28 px | 2 px | 保存 |
| 输出格式 | PNG / JPEG | PNG | 不适用 | 保存 |

- 上述 px 均为**最终图像物理像素**。显示器缩放只改变控件、命中热区和提示的 DIP 尺寸，不把线宽、字号或颗粒再乘 DPI。长图编辑的视图缩放也不改变图像参数。
- 标注默认颜色沿用红色 `#FF3B40`。编号为红色圆圈与清晰的居中数字，由绘图和文字布局生成，不依赖有限的 Unicode 带圈数字字形。
- 显式调参时：有选中的同类对象，同时更新该对象和该工具默认值；没有选中对象，只更新后续新建默认值。仅选择旧对象可显示它的参数，但不改写默认值。
- 绘制中调节线宽改变当前整条笔画或当前形状，仍是均匀线宽，不增加可变宽笔画模式。一次连续绘制、拖动或滚轮手势作为一次撤销；撤销对象编辑不回退已经保存的工具偏好。
- 滚轮数值达到上下限后保持边界值。数值框允许输入过程中暂时为空，提交时必须为范围内整数；非法提交给出明确范围提示并保留上次有效值，不写入配置。滑杆和滚轮始终产生合法值。
- 参数变化即时更新预览，经现有有界后台配置写入器合并保存。不得在 UI 线程逐个滚轮事件编码图片或同步写盘。

### 1.2 开关与恢复默认

矩形、箭头、画笔、文字默认开启；长截图、马赛克、编号、取色四个新工具默认关闭。八个工具均可在截图设置页配置，开启才在工具条出现。尚未实现的功能不得提前暴露可用按钮或无效开关；按 F08–F11 逐项接入对应新工具开关。

“恢复截图默认设置”只恢复截图相关偏好：操作提示开启、标注颜色 `#FF3B40`、三个独立线宽 3、字号 24、圆角 0、PNG、颗粒 12、编号直径 28、原四工具开启、新四工具关闭。保留主题、热键、开机启动、保存目录及首次提示标记；不改写当前已经创建的标注对象。

## 2. 交互和状态约定

### 2.1 普通截图与直接编辑

- 初次框选仍支持窗口吸附和拖选。选区边缘及八个控制点在任意普通标注工具下可直接调整，标注保持在冻结底图坐标，裁剪只影响最终输出范围。
- 当前工具点击同类型已有对象优先编辑，空白处创建。矩形拖轮廓移动、拖控制点改尺寸；箭头拖主体移动、拖端点改长度和方向；画笔沿笔迹命中后整笔移动，不做节点编辑。
- 同类对象按可见层级从上向下命中；矩形内部空白可新建嵌套形状。输入优先级固定为：工具控件 → 文字编辑或已开始的拖动 → 截图边线及控制点 → 已选对象控制点 → 同类对象轮廓/笔迹 → 空白新建。重合时依此裁决，不让新建操作抢走编辑；已经捕获鼠标的手势持续到结束。
- 文字工具点击已有文字内部直接重编，边框拖动移动，旋转手柄调整角度。沿用当前实现：旋转文字进入文字编辑时暂时水平，提交后恢复角度。中文 IME、文本选择、换行及文本快捷键优先处理；未提交草稿失败时保留。
- 无绘图工具激活时，拖选区内部可移动整个选区；有绘图工具激活时，按住空格拖动移动选区。文本编辑期间空格用于输入，不触发选区移动。点击当前工具可取消其激活，进入无绘图工具状态。
- 每次完整拖动仅记录一次历史。Esc 取消当前拖动并恢复之前对象；无活动操作时取消截图。删除、重编和旋转均继续支持撤销/重做。

### 2.2 滚轮分工

- 普通编辑画布上的滚轮修改当前可调参数：线宽、字号、马赛克颗粒或编号直径。无可调工具时不修改参数。
- 文本编辑状态下接入字号调节时，必须保留中文组合输入、光标和草稿，不能通过结束截图或清空编辑器实现。
- 设置页的普通内容区域滚动页面；只有参数控件获得交互焦点时才调节该控件，避免滚动设置页意外改值。
- 长截图采集期间滚轮用于滚动目标内容；长图完成编辑后，主画布滚轮恢复调当前工具参数，右侧预览或滚动条用于浏览长图。贴图窗口现有滚轮缩放不变。

### 2.3 马赛克、编号与取色

- 马赛克是可编辑的矩形遮挡对象：拖绘覆盖区域，拖内部移动，八点调整覆盖尺寸。滚轮调整**颗粒大小**，不缩放覆盖区域；参数条明确标注“颗粒”。预览、复制、保存和贴图使用一致的像素化结果。
- 编号点击插入，按本会话创建顺序显示 `1…N`，拖动移动；滚轮改变圆的直径。删除后其余编号连续重排；撤销恢复对象和顺序，重做再次重排。新普通截图及新长图文档从 1 开始。
- 取色只在有效截图区域内工作，采样**冻结底图的原始像素**，长图采样拼接底图；不采样标注或马赛克的显示结果。透明显示器间隙显示“无像素”，不伪造黑色，也不复制虚构颜色。显示颜色块及编码；每次进入取色工具默认 HEX。**每按一次 Shift 切换 HEX/RGB，松开后保持当前格式，再按一次切回**。忽略按住 Shift 的自动重复，格式不写配置、不跨会话保存。
- 点击复制当前格式字符串，并留在截图会话中继续取色。复制失败提示并保留当前状态。取色浮层、光标、选区线与工具条不得成为采样来源；不新增放大镜。

### 2.4 长截图：采集与完成后编辑

状态顺序为：`普通截图编辑 → 长截图初始化 → 滚动采集 → 长图静态编辑 → 输出/取消`。长截图只做用户滚轮驱动的纵向采集，不做自动滚动、横向拼接或滚动录屏。

1. 用户启用长截图功能并进入该工具时，**立即清空全部已有标注、当前文字草稿、撤销栈和重做栈**，沿当前选区开始全新长截图。不是隐藏旧标注，也不建立可撤销的清空操作。初始化失败或取消均不得恢复这些已丢弃内容。首版限单屏内固定区域；跨屏选区提示重新框选单屏区域，不静默缩减。提示框选可滚动正文，避开固定页头、底栏及悬浮内容，不自动去页头。
2. 采集期间固定视口及目标内容区域，右侧实时显示已接收长图预览。滚轮送达目标内容，滚动中连续读取中间帧并尝试匹配，收尾时再确认缺段。截图 UI 和右侧预览不能混入捕获结果。禁止把冻结编辑遮罩当作正在滚动的源。
3. 根据相邻帧纵向重叠内容去重并追加新增行；相同帧不追加。无法可靠匹配、目标移动/缩放、捕获失败或资源不足时暂停追加，保留已成功拼接部分并明确提示。反向滚动不产生重复段，不静默猜测错误接缝。
4. 点击完成后停止捕获并进入长图静态编辑；按宽度适配画布，从顶部显示。右侧缩略图可点击、拖动及滚轮定位，滚动条同样可浏览。主画布坐标转换至长图物理像素，不能把视图缩小后的坐标写入标注。
5. 长图静态编辑支持普通截图中已启用的标注、取色以及复制/保存/贴图；不得再次追加采集，不新增裁剪面板或 Ctrl+滚轮缩放。输出是完整长图，不是当前可见视口或缩略图。
6. 长图高度最多 **32768 px**，拼接原始 BGRA 像素最多 **256 MiB**，两项先到者为准；按 `width × height × 4` 检查溢出和容量。此限制是原始像素预算，不是进程总内存承诺；临时帧、缩略图、撤销及 GPU 资源须分别有界，不能长期保存多份完整长图。

取消按钮或采集中的 Esc 结束整个长截图会话；不新增同会话返回旧普通截图的入口。下一次重新截图默认普通模式。预览优先放选区右侧，空间不足贴屏幕右侧，不改选区；捕获排除自身界面失败时不得继续错误采集。

长图采用分块或仅为可见区域建立渲染资源，不能假定 32768 px 高图能作为一个 GPU 位图成功创建。异步任务携带会话代次和取消标记，退出后晚到帧不能改写下一次会话；所有结束路径停止捕获、释放帧池和临时缓冲。

### 2.5 输出与圆角

- 在最终成图范围应用圆角，实际半径为配置值与图像短边一半中的较小值，避免极小选区出现无效几何；设置值本身不随选区大小被改写。
- PNG 保留圆角外透明像素；JPEG 将透明区合成到白底，编码质量固定 90%，扩展名使用 `.jpeg`。不增加未批准的 JPEG 质量设置。
- 设置中的格式是另存为默认格式；对话框允许在 PNG/JPEG 中选择本次格式，实际编码、文件过滤器和扩展名保持一致。用户取消或保存失败均返回原编辑状态。
- 复制、保存、贴图使用同一份干净合成语义，排除控件、控制点和提示。复制图像保留现有 Windows 图像剪贴板兼容格式；设置 JPEG 不把剪贴板图片强制变为有损文件。
- 贴图接收已经完成圆角处理的图像；保存或复制已成图贴图时不按后来改动的圆角设置再次裁切。输出和文件写入继续使用既有受控后台工作线程。

## 3. 代码接入与配置迁移

### 3.1 复用边界与必要接口调整

| 子系统 | 现有入口 | 本轮接入方式 |
| --- | --- | --- |
| 标注模型和历史 | `src/core/annotation.rs` | 复用 Object/Shape/Editor、命中与历史；增加同工具编辑和马赛克/编号对象；把 Tool 的业务标识与工具条数组下标分离 |
| 选区和会话 | `src/core/selection.rs`、`src/core/session.rs` | 增加整边命中、显式选择手势和长截图阶段；保留物理坐标、取消及晚到帧保护 |
| 输入路由与参数 | `src/platform/windows/preview.rs`、`text_input.rs` | 按控件/文本/活动手势/画布路由；接入滚轮、数值输入和工具状态，不把新逻辑继续集中进主消息循环 |
| 绘制和布局 | `selection_render.rs`、`annotation_render.rs`、`toolbar_icons.rs` | 绘制真实参数控件和动态工具列表；预览与成图共用对象几何及样式；长图增加文档坐标到视口坐标的明确转换 |
| 设置与存储 | `src/core/config.rs`、`preferences.rs`、`config_store.rs`、`settings_layout.rs`、`settings.rs` | 扩展 Config、版本迁移、设置布局和异步保存；共享参数范围定义，避免工具条与设置的数值再次不一致 |
| 合成与编码 | `composition.rs`、`output.rs`、`png.rs` | 合成阶段接入马赛克/编号/圆角；在现有 WIC 路径扩展 JPEG，输出请求携带格式和成图选项，不根据最终文件后缀猜测全部行为 |
| 捕获与长图 | `capture.rs` 及新增独立滚动捕获/拼接模块 | 平台层负责目标窗口和帧生命周期；核心层接收有界像素帧，负责重叠检测、去重、尺寸和容量判断，不接收 HWND/COM |

上表未写目录的文件位于 `src/platform/windows/`。不要求机械重命名既有模块；要求按职责拆出新功能，保持核心可测试、平台资源局限于 Windows 层。

- 使用稳定的工具/动作标识表达矩形、箭头、画笔、文字、长截图、马赛克、编号、取色及输出动作；绘制、命中、提示和键盘导航从同一份可见项列表派生，禁止用旧的 `0..=10` 索引推断动作。
- 样式值在对象中以物理像素保存，在配置中以有范围约束的整数保存；视图变换和控件 DPI 单独处理。操作同一对象时不得因鼠标进入另一块屏幕重新放大样式。
- 独立保留“当前选中对象参数”和“工具的新建默认值”，避免选择旧对象触发配置写入。配置保存失败不破坏会话中的有效编辑。
- 渲染新增类型时同时实现预览和输出，不得仅在桌面覆盖画出效果。马赛克从图像像素生成效果，移动/删除对象后可重新合成冻结底图；不反复破坏性修改唯一原图。
- 不新增外部公共服务/API，不持久化标注工程或截图历史。若需要新增依赖，先记录具体用途、许可和 Release 体积影响；现有系统图形与编码能力能覆盖时优先复用。

### 3.2 配置版本与兼容规则

F02 将当前配置从 `version=1` 升级为 `version=2`。继续使用现有本地键值格式、64 KiB 限制、原子替换、有界写入队列与损坏配置保留机制，不为本轮引入配置框架。

| 字段组 | 迁移/新增规则 |
| --- | --- |
| 现有颜色、热键、主题、提示、保存目录、首次提示标记 | 保留有效旧值；开机启动仍由既有系统设置路径管理 |
| 三个线宽 | 旧 `stroke_width` 的有效数值复制为矩形、箭头、画笔各自的物理 px 默认值；不乘迁移机器 DPI |
| 文字字号 | 旧 `text_size` 数值保留，F03 后按物理 px 使用，不按当前屏幕二次换算 |
| 圆角、输出格式、颗粒、编号尺寸 | 缺失字段分别默认 0、PNG、12、28 |
| 工具开关 | 缺失时原四工具 true、新四工具 false；关闭与实现尚未完成必须区分 |

采用明确字段表达 `rectangle_width`、`arrow_width`、`pen_width`、`text_size`、`corner_radius`、`output_format`、`mosaic_size`、`sequence_size` 及八项工具启用状态。Config 中不保存取色 HEX/RGB 的临时模式。

- v1 升级先完整解码和验证，再一次性提交迁移结果。任何迁移失败不覆盖原文件、不部分应用；错误按现有可恢复配置策略提示。
- v2 的新增字段可逐阶段落地，缺失取本方案默认值；未知键在合法文件范围内往返保留，避免新旧阶段工具写回时丢失无关配置。无需额外序列化框架。
- 保留对不支持的未来配置版本的保护：不以当前默认值静默覆写未来版本文件，不承诺向后降级运行兼容。
- 旧版的“px”随 DPI 放大，本轮统一为物理 px 后高缩放屏幕的实际显示粗细可能改变，这是已确认的单位调整，不能为维持旧显示再暗中乘 DPI。

### 4.1 阶段实现时必须同步的界面行为

- F07 人工复测优化后，工具条从首个可见绘图工具开始。F12 在绘图与采集工具之后、固定输出之前显示撤销，窄屏收纳绘图与采集工具时撤销仍直接可达。
- 最终顺序为：**矩形、箭头、画笔、文字、马赛克、编号 | 长截图、取色 | 贴图、保存、复制 | 取消**；隐藏关闭工具并收紧空位，空分组不留下孤立分隔线。输出和取消不属于可隐藏工具。
- 当前工具使用松绿轻高亮；复制为纯图标操作，保留名称提示、可辨焦点、悬停和忙碌状态，不增加深色实心按下标识。功能名称、热键提示不得随数组位置错配。
- 截图工具条仍横排：选区下方优先，其次上方，再安全收纳于实际显示器内；不能停在显示器间隙。长图窗口按右侧预览和主画布可用空间布局，不覆盖可操作区域。
- 尚未完成的后续工具不会在前序版本出现空按钮。F08–F11 分别添加实际可用工具时，其默认开关仍为关闭；用户主动开启后才显示。

## 5. 验证、文档更新和本地版本门槛

每个阶段在开始时复核工作树与前序验收记录，完成以下闭环：

1. 读取对应设计草图和验收组，实施限定范围，补充有意义的核心单元测试与平台集成检查。保留用户及其他会话修改，显式暂存本阶段文件。
2. 按 [验收计划](ACCEPTANCE_PLAN.md) 运行相关自动检查、真实应用交互、浅深主题截图和实际输出检查，使用 [模板](validation/FEATURE_ACCEPTANCE_TEMPLATE.md) 保存实测环境、步骤、结果、证据及缺陷复测。初始状态必须为“待执行”。
3. 发现直接相关阻断缺陷时修复并复测，不为按时打 tag 跳过。缺少真实多屏/HDR等条件时保留待实机验证，沿用已批准的限制，不把本轮构建成功写成这些环境通过。
4. 在最终验证前将目标应用版本写入 `VERSION`，并更新相关用户说明。使用打包脚本构建目标版本和 ZIP，再执行最终验收与解压包烟雾检查。报告记录实际被测源码及 EXE/ZIP SHA-256，核对版本一致。若验证后又改应用代码或资源，重新构建并复测受影响项。仅补充报告的提交须明确二进制来源。
5. 检查 `git diff --check`、暂存 diff 和最终工作树，形成有意义的本地提交；在已通过验收的对应提交上创建带说明的本地版本 tag。**不推送分支、不推送 tag、不创建远端 Release**。

记录必须明确区分“实现完成”“自动检查通过”“真实 GUI/输出通过”和“仍待实机验证”。每次交接给出下一未完成阶段、关联提交、验收证据、遗留项及阻塞条件，不通过重写历史报告把旧失败样本改成已通过。

方案与草图于文档基线提交确认。逐阶段实施和验收状态见 [当前进度](PROGRESS.md)。

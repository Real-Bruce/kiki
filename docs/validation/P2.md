# P2 单屏输出、坐标与取消验证

日期：2026-11-06。状态：进行中。用户明确要求多屏实机验证先跳过，原因是没有验证环境；跨屏功能和原验收目标保持不变。本文不将合成数据测试称为多屏实机通过。

## 本轮改动

- 将显示器枚举拆到平台 display 模块，逐屏记录物理边界、设备名称、系统缩放、旋转方向、刷新率与色彩模式。捕获前后比较两份描述，配置发生变化时放弃本次结果。
- HMONITOR 只留在捕获线程内；交给 UI 的 DisplayInfo 不含原生句柄或 COM 对象，没有添加 unsafe Send。
- 原始 BGRA 图像的尺寸、行步长和 Vec 长度改为私有，只开放固定长度像素切片，避免外部模块破坏复制操作的边界保证。
- 新增独立区域裁剪，保留全局物理坐标，未覆盖区域保持透明；该 API 目前用于开发输出验证，正式编辑器将在后续接入。
- 取消信号实际进入工作线程：分屏捕获前、首帧等待、读回行循环和返回前检查；首帧等待按最多 10 ms 的片段检查信号，取消后仍通过 RAII 关闭 session/pool。10 ms 不是对 D3D 创建、Map 或系统调用阻塞时间的保证。
- UI 在显示变化和退出时发送取消信号；原有 SessionGate 继续拒绝晚到帧。锁屏通知与真实显示热插拔仍未完成验收。
- 开发探针新增 --cancel-stress：实际 StartCapture 后置取消信号，检查返回 E_ABORT，连续 100 次后在同一进程和线程恢复正常捕获并写 PNG。
- 只增加 windows-rs 的 Win32_UI_Shell_Common feature，以读取官方逐屏缩放值，没有新增 crate 或应用运行时。

## 实机与输出证据

沿用 P1 的 Windows 11 / i5-12400 / Intel UHD 730 测试机和 Release 模式。当前实际枚举为：

| 项目 | 值 |
| --- | --- |
| 显示器数 | 1 |
| 物理范围 | (0,0)–(1920,1080) |
| 设备名称 | \\.\DISPLAY1 |
| 缩放 / 旋转 / 刷新率 | 125% / 0° / 60 Hz |
| 色彩模式 | SDR |

使用 diagnostics Release 执行 --probe，退出码 0，结果在 artifacts/p2/single：

- capture.png：真实 1920×1080 桌面，已打开检查。
- capture-region.png：从物理位置 (480,270) 裁取 960×540，已打开检查。
- capture.txt：记录本次捕获及读回与末尾配置核对耗时 90.3319 ms，以及完整屏幕描述；这不是热键到界面可操作的端到端时延。

脚本 scripts/Verify-Region.ps1 使用独立的 Windows System.Drawing PNG 解码器，逐行比较导出裁剪图与整图对应区域的全部 BGRA 数据。实际比较 518,400 个像素，尺寸与所有像素一致。此 PowerShell/.NET 验证工具不随应用分发。

取消探针的 CSV 沿用 capture_ms 列名，数值是该次进入捕获到取消返回的总时间，不是纯取消响应时延。没有强制清理工作集，没有删掉首样本。即时释放后的驱动清理仍可能异步完成，因此同时记录静置样本。

## 检查结果与限制

- 默认和 all-features 的 all-targets 严格 Clippy 通过；6 项测试通过。
- 新增有意义的全边界裁剪测试，覆盖负原点、源行步长、内部裁剪、四边扩展、透明区与空范围。此前的几何极值、透明间隙、会话代次、PNG 像素往返继续通过。
- 默认不含开发探针的 Release 构建成功，为 361,472 字节，较上一阶段增加 5,632 字节；尚无最终完整功能体积结论。
- 曾因遗漏 Interface trait 及错误地携带 HMONITOR 跨线程而编译失败，已通过职责拆分解决，没有扩大 unsafe 或增加全局 suppress。
- 多屏、混合 DPI、负坐标显示器、竖屏、真实屏幕间隙：按用户要求暂缓实机，保留自动测试与后续验收项。
- HDR 到 SDR：尚未实现/验收；当前高级色彩模式明确报错。未将 SDR 输出当作 HDR 通过。
- 真实热插拔、锁屏、设备丢失与更换缩放期间的完整恢复：待后续验收。当前仅有显示描述比较、消息取消路径及受控取消/恢复证据。
- P2 仍不能标为全部完成；下一步继续补齐平台取消/错误路径与色彩处理，并推进可独立实施的界面工作。

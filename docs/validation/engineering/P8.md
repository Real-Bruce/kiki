## 构建和依赖

- Rust 1.88.0，目标 x86_64-pc-windows-msvc，使用 Cargo.lock。rustfmt、默认及全特性严格 Clippy、普通 Release 构建通过。默认和全特性各通过 41 项测试。
- dumpbin /DEPENDENTS 显示直接导入均为 Windows 系统 DLL 或 API Set，无独立 VCRUNTIME、MSVCP 或其他随包 DLL。构建配置启用静态 MSVC CRT。系统组件在进程中加载 Windows 自带的 msvcp_win.dll 和 ucrtbase.dll。 [Microsoft CRT 部署说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/develop/using-the-microsoft-c-runtime-with-user-mode-drivers-and-apps)
- 标准库许可保留工具链随附的 COPYRIGHT-library.html 和 licenses。 [Rust 许可说明](https://github.com/rust-lang/rust/blob/main/COPYRIGHT)

## 解压实测

- Windows 11 Pro x64，构建 26300.9711。以解压目录为工作目录，清空继承的开发环境变量，PATH 只包含 Windows 和 System32。第一次启动前当前用户尚无 kiki 配置，程序启动后按预期写入首次使用配置。
- 普通 EXE 成功启动并打开设置，界面显示开机启动关闭。默认 Ctrl+Alt+A 已发送，进程随后载入 GraphicsCapture.dll。普通版截图和贴图浮窗无法由电脑操作工具枚举，后续由用户操作。
- 用户使用解压版保存窗口和区域截图。实际解码并查看 artifacts/kiki_20261107_222555.png 和 artifacts/kiki_20261107_222627.png，尺寸分别为 2058×1549 和 672×277。
- 用户补测标注后保存 artifacts/kiki_20261107_223243.png。解码尺寸为 874×347，检查可见红色矩形和箭头，检测到 8,905 个默认标注色像素。截图工具条和选区边框未出现在成图中。
- 用户确认复制后粘贴到 Word 成功，应用内 Ctrl+P 打开独立置顶贴图和 Esc 关闭均通过。
- 启动和捕获触发后各枚举一次进程模块。除解压出的 kiki.exe，载入文件均位于 Windows 目录内，含系统 WARP、Direct3D、Direct2D、DirectWrite、GraphicsCapture 和 WIC。
- 本机安装了开发工具。上述实测使用新解压目录、首次配置和最小进程环境，独立的无开发工具 Windows 系统仍待验证。

## 自动打包与标签发布

- 本机以 Rust 1.88.0 构建 v0.2.1 ZIP，解压到含中文与空格的目录后核对 16 个文件、ZIP 校验值及 EXE 哈希。EXE 文件版本和产品版本为 `0.2.1`，Windows SDK 的 `mt.exe` 提取出 `0.2.1.0` 清单，并确认 `PerMonitorV2`、长路径和 `asInvoker` 设置。
- 在独立的中文与空格路径下将 `VERSION` 改为 `0.2.2`，同步后 `Cargo.lock` 仅变更 kiki 包的版本。按工作流参数打包生成 `kiki-v0.2.2-windows-x64.zip`，解压确认 EXE 版本 `0.2.2` 和清单版本 `0.2.2.0`。最终脚本再次生成 527,003 字节 ZIP，包含 16 个文件，SHA-256 为 `5ccd47c438e588bcba87c155fbb7ffb9c6d97c91ba15fcb9b3567c8f438af31f`，并清理临时目录。
- 实测 `-Tag v0.2.2` 在版本为 `0.2.1` 时于构建前报错，直接构建时 `VERSION` 与 Cargo 版本不符也会报错。PowerShell 脚本语法与工作流 YAML 解析通过。
- rustfmt、全特性严格 Clippy 和普通 Release 构建通过。受限会话中 40 项测试通过，4 项系统集成测试受注册表、热键或剪贴板权限影响。正常 Windows 会话重跑，全特性 44 项通过。
- 本机验证覆盖版本同步、构建及打包。GitHub Actions 触发和 Release 上传待首次推送新版本标签时验证。 [GitHub 标签触发文档](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#push) · [GitHub CLI 发布文档](https://cli.github.com/manual/gh_release_create)

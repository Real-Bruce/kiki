# P1 工程与原生风险验证

日期：2026-11-06。状态：P1 单屏 SDR 基础链路验收已收口；跨环境及最终产品验收仍待后续阶段，首版尚未完成。

## 工程与依赖

- Rust 1.88.0（6b00bc388）、Cargo 1.88.0、edition 2024、x86_64-pc-windows-msvc。
- MSVC 14.44.35207 工具目录，dumpbin 14.44.35213，Windows SDK 10.0.26100.0。
- 唯一直接依赖 windows = 0.61.3，MIT/Apache-2.0，固定版本并提交 Cargo.lock。用于 Win32、WinRT WGC、D3D11、Direct2D、DirectWrite、WIC、COM 和系统诊断；没有 GUI 框架或异步运行时。
- EXE 使用静态 CRT、GUI subsystem 和嵌入式 PMv2 manifest。Release 使用 opt-level=s、LTO、单 codegen unit、保留 unwind 以在 Windows 回调边界捕获 Rust panic。
- 本轮性能所用 Release EXE 为 399,872 字节（含显式开发探针）；此数不是最终全部功能体积。
- dumpbin /dependents 仅列出 Windows 系统 DLL 与系统 API 集，没有额外 VC runtime DLL。尚未在无开发环境机器验证。

## 发现并修复

1. 预览关闭后保留旧 HWND，可能遇到句柄复用：改为窗口销毁时清除共享的存活状态。
2. Start-Process -WindowStyle Hidden 的启动参数使第一次 ShowWindow 被忽略：显式请求窗口显示并置前，复测可见。
3. 第一次压力测试第二次捕获发生 0xC0000005：增加主线程 STA 和进程级 MTA 保活，避免捕获线程退出时使缓存 WinRT 工厂失效。
4. 后续压力测试在第 75 次前后再次发生 0xC0000005；Windows 应用日志报告 IntelControlLib.dll_unloaded。保持 DXGI 工厂到应用退出后，连续两轮各 100 次捕获正常结束，退出码均为 0。此结论只覆盖当前驱动，仍需其他硬件回归。
5. CPU 读回增加纹理格式、纹理尺寸、行步长与映射跨度检查；拒绝无效缓冲，不输出错误图像。

参考：[微软关于缓存工厂失效的分析](https://devblogs.microsoft.com/oldnewthing/20211105-00/?p=105878)、[WGC 捕获与 HDR 注意事项](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture)。最终修复依据本地复测结果，不将相似案例当作直接证明。

## 测试环境和方法

- Windows 11 专业版，10.0.26300，build 26300。
- Intel Core i5-12400，12 逻辑处理器；系统报告物理内存 34,019,622,912 字节。
- Intel UHD Graphics 730，驱动 32.0.101.7088；还安装 GameViewer Virtual Display Adapter 15.6.5.199。
- 当前枚举 1 个活动显示器，1920×1080、60 Hz、SDR。桌面缩放数值未独立记录，不能作为高 DPI 验收证据。
- WGC 计时从 desktop() 入口开始，到取得全部屏幕的自有 CPU 像素为止，包含本次枚举、设备创建、首帧等待和读回；不含消息分发、Direct2D 上传或窗口首次呈现。
- 每次新建捕获 session，取得一帧后关闭 session/pool 并释放帧与纹理；没有后台持续采集。100 次在同一探针进程中执行，逐次保存样本，不剔除首样本，不强制清理工作集。
- 资源使用 GetProcessMemoryInfo / GetProcessHandleCount / GetGuiResources；每次释放 Image 后即时采样，末尾等待两秒再采样。total_working_set 是总工作集，不能冒充私有工作集。

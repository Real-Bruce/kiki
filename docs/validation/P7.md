# P7 性能、生命周期与最终回归

P7 本机回归与阶段验收完成。最终构建在单屏 SDR / 125% 通过时延与资源目标，200% 资源目标通过，后续截图时延存在未达标的复测。跨环境待验项目见验收矩阵。

## 环境与口径

- Windows 11 专业版 10.0.26300；Intel Core i5-12400，6 核 / 12 逻辑处理器；物理 RAM 34,019,622,912 字节。
- Intel UHD Graphics 730，驱动 32.0.101.7088。CIM 另列 GameViewer Virtual Display Adapter；实际捕获枚举为一块 DISPLAY1：1920×1080、125%、60 Hz、SDR、横屏。不能把虚拟适配器登记值当成第二块活动显示器。
- Rust 1.88.0 / MSVC x64，Release。性能采样使用 diagnostics 构建；普通构建排除采样代码与 ToolHelp / ProcessStatus 开发入口。
- 独立进程启动称为进程冷启动，使用正常系统文件缓存，不代表重启后的磁盘冷缓存。所有样本保留，不删异常值，不压工作集，不循环刷新桌面。
- 私有工作集取 GetProcessMemoryInfo 的 PROCESS_MEMORY_COUNTERS_EX2.PrivateWorkingSetSize；private bytes、总工作集分别记录，不相互替代。
- GPU 使用 IDXGIAdapter3::QueryVideoMemoryInfo，记录适配器 0 / 节点 0 的本进程 local / nonlocal 用量。UMA 上 local 不是独立显存容量，不能直接与 CPU 工作集合计。

## 可复测方法

先使用 `cargo build --release --features diagnostics`。

```powershell
./scripts/Measure-Startup.ps1 -OutputDirectory artifacts/performance/新的启动目录
./scripts/Measure-Performance.ps1 -FirstOnly -OutputDirectory artifacts/performance/新的首次截图目录
./scripts/Measure-Performance.ps1 -OutputDirectory artifacts/performance/新的生命周期目录
./scripts/Measure-Idle.ps1 -ProcessId <待采样进程编号> -OutputDirectory artifacts/performance/新的闲置目录
```

- 启动：30 次独立进程，OS 创建时间到托盘、配置/热键和窗口类就绪；每次确认热键注册成功。
- 首次截图：30 个独立进程各取第一次；计时从向已注册 ID 投递 WM_HOTKEY 前开始，经正常捕获工作线程、主线程结果接收、可见预览首次绘制，止于 DwmFlush。包含 UI 队列、GPU 初始化和合成等待；不包含物理键盘/系统向应用投递热键之前的时间。它是应用端响应基准，不能写成物理热键全链路测量。
- 后续截图与生命周期：同一进程连续 200 次真实桌面捕获。前 100 次经 Esc 取消，后 100 次使用真实桌面加中文/矩形/箭头/画笔诊断标注，通过普通后台合成、可见贴图、关闭全部路径。每轮关闭后泵送 300 ms，再记录资源。首次样本单列，199 个后续样本全部计入。
- 闲置：200 轮结束后没有会话、贴图或设置窗口，观察至少 60 秒。CPU 是进程 kernel+user 增量 / 实际墙钟 / 12 ×100%。内部探针只保留一秒定时器读 CPU，不在每秒进行昂贵的 DXGI / ToolHelp 采集；资源另在区间末读取。外部 Measure-Idle 可对无内部探针的普通驻留流程读取 60 秒快照，不向目标进程加载代码。
- 隔离：显式 `--isolation-probe <目录>` 分别执行 100 次仅采样、预览创建/绘制/销毁、后台真实捕获、后台 WIC/中文成图，用来区分计量开销与产品资源。
- 4K：`--pin-stress <目录>` 执行 100 轮，每轮四张独立 3840×2160 渐变图的原生隐藏表面绘制/关闭。它用于大图资源压力，不冒充可见 GUI 交互或 4K 显示器时延。
- 上述脚本使用新的空目录，保留原始 CSV、环境、二进制 SHA-256、失败目录。配置隔离到每轮目录，未写用户实际配置或实际 Run:kiki。所有像素与运行记录留在被忽略的 artifacts，不提交。

## 本轮修正与比较

- 原实现为每张预览新建独立 HWND render target / 隐式设备。隔离测试的预览句柄在首轮初始化后每轮增加约 4；仅采样 100 次始终 155，后台捕获首次初始化后始终 653。首个完整 200 轮基线最终 1,396 个句柄，不能判为生命周期通过。
- 仅共享旧 HWND 绘图工厂虽使预览句柄趋稳，但完整循环 GPU local 仍约 58 MiB、私有工作集约 78 MiB，因此未采用。
- 预览、设置与贴图改用同一个显式 D3D11 / D2D 设备，各有独立交换链和图像。设置主题不再重建整个图形域；调整窗口尺寸通过解绑 / ResizeBuffers / 重新绑定，保持 DPI。正常绘制使用 Present(0)，没有新增持续绘制。
- 关闭最终表面后立即清除未使用缓存，并在 200 ms 后仅再清理一次；有其他窗口使用时保留资源。设备在 Runtime 的 COM 退出之前释放。
- 试验过空闲时销毁整个设备，以减少后台工作集；该机上重新创建设备重新出现每轮句柄增长，保留其失败数据并撤销该方案。不能用较低内存掩盖生命周期回退。
- 捕获直接将映射的监视器行复制到物理桌面缓冲，省掉一个额外的整监视器 CPU 图像及一次 blit；保留 stride / 边界 / 取消检查、透明屏幕间隙和 SDR 不透明像素语义。单块 4K 少一份约 31.6 MiB 的临时 CPU 图像。
- 核查 DXGI 窗口关联：应用负责窗口尺寸与模式变化，显式禁用 DXGI 的自动窗口消息处理及 Alt+Enter 接管。

原始实验目录：`artifacts/performance/p7-{startup,first,lifecycle,isolation,shared-factory,shared-lifecycle,shared-device-isolation,device-startup,device-first,device-lifecycle,idle-release-lifecycle,retained-factory-lifecycle,window-association-lifecycle}`。其中 idle-release 轮被主动中止以撤销已证实的句柄回退，不算完成样本；其 CSV 原样保留。最早的 idle CPU 包含每秒昂贵采集开销，不与普通驻留 CPU 混称。

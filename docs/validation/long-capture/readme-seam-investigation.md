# README 图片区长截图接缝排查

2026-11-23，Windows，源码 v1.0.21，基线提交 `0e3610a`。本轮定位接缝拒绝的条件，修复和 IDE 实机复验留给下一阶段。

## 现场线索

用户在 IDE 的 README 渲染预览中继续滚动，长截图预览停在 1057 × 2373 px 并提示“未找到可靠接缝”。选区里的 Ctrl+1、左侧导航和按键说明与 README 的[快捷键配图](../../screenshots/settings/shortcuts-light.png)一致。左侧导航也画在 PNG 里，排查时应让它随 README 一起滚动。附件右侧已拼接缩略图的末端几乎全是背景。在原附件横坐标 1675–1860 范围内，纵坐标 595–651 的 57 行像素逐行完全相同。缩略图经过降采样，只能作为查找原始帧的线索。

## 用实际拼接器重放

将 README 的[通用配图](../../screenshots/settings/general-light.png)按原像素解码，横坐标从 15 开始裁 1057 px，视口高 362 px，坐标从 0 开始。在临时驱动中直接调用本版 `Stitcher::new` 和 `accept(frame, true)`，从图顶依次输入间隔 16 px 的帧。输入来自同一张 PNG，位移已知，重叠区像素完全一致。下表记录实际运行结果。

| 帧顶位置 y（px） | 重叠 | 观察 |
| --- | --- | --- |
| 384 → 400 | 346 行 | 重叠内有 18 种完整像素行，返回 `Added`，累计图高 762 px |
| 400 → 416 | 346 行 | 只有 +16 一个完全匹配的候选，但重叠内只剩 2 种完整像素行，返回 `Unmatched`，累计高度停在 762 px |
| 420 → 460（独立初始化） | 322 行 | 两张视口图逐字节相同，返回 `Known`。即使真实下滚 40 px，单凭这对帧也无法确定距离 |

这解释了为什么慢滚也会失败。即使前后帧有约 96% 重叠，唯一候选仍可能在最后的细节检查被拒。首次拒绝保留旧位置，继续下滚时，同一块空白可对应许多位移，之后即使出现新文字，也可能已经失去与已拼接末尾的联系。另一组对照中，用同高的快捷键原图裁片（x=0，宽 1057）从 y=505 下滚到 520，整帧像素相同；从同一锚点 505 比较 y=570，在当前搜索范围内有 253 个完全匹配的位移（20 至 272 px）。后者不能从像素唯一确定该追加多少行。

## 可单独修正的候选判定

在一个有明确锚点的合成对照中，构造 1057 × 362 px 的前后视口，向下移动 60 px。源图第 185–230 行绘制逐行唯一的纹理，第 370 行加入新内容，其余为同一背景。真实位移 +60 的重叠区有 302 行、47 种行指纹。另有 +237 至 +272 共 36 个位移，只匹配了短段纯色背景。实际拼接器一遇到第二个完全匹配的位移就返回 `Unmatched`，使空白候选否决了唯一有纹理证据的候选。

这是可单独写回归测试的误拒。可先验证在统计追加候选是否唯一之前，对每个候选检查足够的匹配细节；保留两个有细节的候选同时成立时暂停的行为。在通用和快捷键两张原图上对 16、40、60、80、120、180 px 位移的扫描未发现同一组合。修正这个顺序后仍需单独处理上表的低细节情况。通用配图的 y=416 与 417 两行在裁片内仅 7 个像素不同，只有一个逐字节候选仍不足以单独证明接缝稳定。

## 代码与后续验证

1. [拼接器](../../../src/core/long_image.rs)的 `Stitcher::accept` 先检查整帧相同，再搜索重叠至少 `max(12, 视口高 / 4)` 行的下滚位移。多个逐像素候选直接返回 `Unmatched`。唯一候选在追加前，还要求重叠内至少有四种不同的行指纹。失败不更新 `viewed`。建议先让测试或 diagnostics 区分多个候选、唯一候选细节不足，以及搜索范围内无可信候选，记录候选偏移和重叠行数。
2. 把上述 16 px 序列作为回归起点，检查能否利用唯一可定位的边界及前序已确认帧验证位移。测试还应包含真正全同的视口、重复图案、回滚和从空白区重新出现的文字。对可以确定的位移按原图逐像素核对，对无法确定的区段保留最后可信结果。滚轮刻度本身不能给出 IDE 内文档的实际像素位移。
3. [采集循环](../../../src/platform/windows/editor/long_capture.rs)在一轮滚动收尾时，仅在最后一次读到的帧为 `Unmatched` 时显示此提示。它保留采集流，等下一次滚轮信号继续。分别在 IDE 中用长短两种选区滚过“通用”图片底部至“快捷键”标题，比较逐格慢滚与连续滚动。用有界的数值诊断记录滚轮时间、WGC 帧时间、匹配耗时、上次可信位置和拒绝分支。若编号内容仍有充分重叠却匹配失败，查缩放或平滑滚动时的重绘；若缺少中间帧，再查[两帧捕获池与读回](../../../src/platform/windows/capture/mod.rs)及滚动收尾时机。

默认 Debug 环境下，`cargo test --workspace --locked core::long_image::tests -- --test-threads=1` 的 5 项与 `cargo test --workspace --locked continuous_scroll_can_append_frames_even_without_a_stable_pair -- --test-threads=1` 的 1 项均通过。本次离线重放证明已有拒绝路径足以造成相同现象；附件没有对应的连续 WGC 原帧，用户现场首次拒绝的位置和原因仍待核实。[v1.0.3 Daily 漏段](long-capture-v1.0.3.md)保留为独立的待验案例。

# v1.0.23 长截图参考框验证

2026-11-23。被测实现随本报告提交。用户在 IDE 的 README 预览里框选 1290 × 180 px 时，连续留白会使原选区多帧像素完全相同。独立滚动窗格的反例表明，应用需要由用户指定同一滚动正文的范围。 [现场附件与排查](multi-image-v1.0.22.md)

## 操作及约束

先框选输出区域，按住 Shift 点击「长截图」，再框选包含原选区的更高正文区域。二次框选复用当前截图的遮罩和框选反馈。第二个框在同一显示器上，与原选区取相同横向范围，只扩展可用于匹配的高度。框选时避开固定栏和独立滚动的窗格。采集后把指针放在原选区内手动滚动。

使用同一个 Windows Graphics Capture 流，预览和成图只包含原选区扫过的连续像素。参考区的接缝须唯一且逐像素匹配，新增位移须小于原选区的高度。遇到疑似歧义、完全相同的整张参考帧或缺行，保留已确认内容。参考行占用现有长截图缓冲预算。 [使用说明](../../USAGE.md#长截图)

## 验证结果

| 检查 | 实测 |
| --- | --- |
| 1290 × 180 px 选区，三张 README 配图，16 px/步 | 直接拼接到 y=576 首次暂停，输出保留 740 行。通过 620 px 高参考框重放 184 次位移，全部成功。成图 1290 × 3120 px，等于源图中原选区连续扫过的像素。参考框在首帧中比原选区上延 48 px、下延 392 px |
| 合成留白与恢复 | 在 500 行相同背景中逐帧拼接，经实际短选区回滚后核对预览及最终像素。一次位移达到输出选区高度时保持上一次成图 |
| Windows 原生入口与输出 | 用实际工具条发送 Shift 点击及二次拖框，使用 286 px 高参考区采集 190 px 高原选区。滚轮一次后预览增至 229 px，导出 509 × 229 px PNG。首帧与原选区、PNG 与拼接底图逐像素一致 |
| 普通入口、回滚和快滚回归 | 普通工具条启动后预览由 286 增至 325 px，输出 PNG 与底图一致。编号文档向下 17 次增至 1170 px，回滚不增长，关闭目标后可开启下一会话。WGC 快滚试验 36 次，每次 83 px，420 × 3248 px 输出与源图一致 |
| 自动检查 | rustfmt、全特性严格 Clippy、默认和全特性串行测试通过。两套各 87 项通过、7 项按需运行。另串行通过上述 4 项 Release 原生用例 |

系统为 Windows 11 x64 build 26300.9974，Intel Core i5-12400，1920 × 1080、125%、60 Hz、SDR。已核对浅色与深色 Release 全特性程序的参考提示、原框尺寸、预览按钮与导出像素，实拍留存于 `artifacts/validation/long-capture-v1.0.23/`。原生参考框单次滚轮至预览更新在浅色与深色各测一次，分别为 81.4 ms、28.3 ms。WGC 快滚 36 次由 GDI 绘制至拼接完成，P50 为 16.327 ms，P95 为 32.887 ms，最大为 33.541 ms。README 离线重放使用 `rustc -O`，只计匹配过程，620 px 参考区的 184 次 P95 为 2.249 ms。原 IDE 场景待实机复验。
